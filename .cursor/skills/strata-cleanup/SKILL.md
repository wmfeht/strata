# Strata cleanup

Run only when the coordinator says the pipeline is done (clean review + QA, or they are stopping after the last round). Produce a human-authored history and one public PR comment.

## Required reads

Read **all** of `working-docs/<n>/` before touching git:

- `plan.md`, `test-cases.md`, `status.md`
- `code-notes.md` (all rounds if multiple)
- `review.md`, `qa.md` (latest and prior rounds if present)

## 1. Squash to a clean human history

Squash pipeline commits on the **staging branch** into a history suitable for human authorship.

Follow repo **Metadata policy** (`.github/workflows/pr-policy.yml`, `CONTRIBUTING.md`):

- Do **not** leave commits authored, committed, or co-authored by an AI coding agent (`Cursor Agent`, `cursoragent@cursor.com`, `Co-authored-by: Cursor`, “generated by” trailers). Those block undraft/merge on `lgse/strata`.
- Rewrite the squashed commit(s) under the **human PR author’s** identity (name + email from that person’s existing human commits on the repo, typically the GitHub account that owns the staging PR). If you cannot determine that identity, **stop** and report; do not commit as `Cursor Agent`.
- Use a Conventional Commit message that matches the intended PR title (`<type>(optional-scope): <imperative description>`).
- Force-push **only** the staging branch after the squash (this step is an authorized rewrite). Never force-push `main`.

## 2. Remove temporary docs

- Delete `working-docs/<n>/` from the branch (the whole folder).
- If the coordinator marked a `docs/<pr>.md` (or similar) guided plan as **temporary for this pipeline**, delete that file too.
- Do not delete lasting product docs. Do not change application/runtime code in this skill.

Commit the deletions as part of the squashed human commit when possible (one commit is preferred). If a follow-up commit is required, it must also use the human identity.

## 3. One final GitHub PR comment

Post **one** comment on the staging PR summarizing review + QA:

- Verdict history (each round’s review + QA)
- Blockers found and whether they were fixed
- Residual nits/suggestions (not blocking)
- Head SHA **after** squash

Do not paste entire working-docs files; summarize.

## 4. Leave the PR draft

Leave the PR **draft** unless the coordinator explicitly says to undraft. Do not merge.

## Report back

Return:

- Final head SHA
- PR comment URL
- Confirmation that `working-docs/<n>/` is gone from the branch
- Whether identity rewrite succeeded

## Guardrails

- Update nothing else in product code.
- Do not open a second PR.
- Do not file new GitHub issues unless the coordinator says so.
